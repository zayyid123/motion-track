# Architecture

Motion-Track is a client-heavy Next.js application. The server has exactly one job: the optional AI relay at `src/app/api/ai-proxy/route.ts`. Everything else — rendering, editing, autosave, and export — runs in the browser.

## Rendering engine

`src/lib/funIsometric/` is the single source of truth for the scene model.

- `fun.ts` defines `Icon`, `Layer`, `Shape`, `Motion`, palettes, views, and the 60 FPS keyframe model. It also exposes `scene()` (builds world transforms once per frame), `render()` (paints a prebuilt scene), and `draw()` (scene + render convenience wrapper).
- `icons.ts` contains the built-in sticker templates.
- `motions.ts` contains the 16 motion tracks.
- `presets.ts` maps preset ids to display labels, descriptions, and factory functions. The inspector and AI prompt read this map, so adding a preset in one place is enough.

A scene is computed once and reused for painting, selection bounds, and hit testing. `src/lib/interactiveEngine.ts` paints the scene plus editor helpers; it never recomputes the scene for a second pass.

## State and history

`src/lib/editor/useStudioState.ts` owns the document and exposes `StudioState` plus a stable `actions` object.

The document type is `StudioDoc`:

```ts
interface StudioDoc {
  icon: Icon;
  paletteId: string;
  palette: Palette;
  facing: View;
  outlineWidth: number;
}
```

Every action goes through `src/lib/editor/history.ts`:

- `commit` adds one undo entry.
- `live` updates the present without touching history (pointer drags).
- `coalesce` collapses rapid changes with the same key (sliders, typing) into one entry.
- `beginGesture` / `endGesture` wrap a drag; a gesture that changed nothing is dropped.
- History is capped at 50 entries. Updates are immutable and structurally shared, so untouched layers keep their identity.

Autosave is a 700 ms debounce to `localStorage` under `motion_track_project_v2`. The draft is restored in a mount effect to keep server and client markup identical.

## Playback

`src/lib/editor/clock.ts` implements `PlaybackClock`, a small external store with three subscription channels: frame, playing, and loop. It uses a single `requestAnimationFrame` loop and advances at a fixed 60 source frames per second, with a catch-up budget so a background tab cannot freeze the UI.

Only components that need per-frame updates subscribe through `src/hooks/usePlayback.ts`:

- `CanvasEditor` repaints on frame changes.
- `Timeline` updates its playhead and timecode.
- The studio shell subscribes only to the playing flag, so panels do not re-render at 60 FPS.

## Geometry and hit testing

`src/lib/geometry/bounds.ts` samples SVG paths through the DOM (cached by path string) and unions shape bounds with stroke width and slab extrusion.

`src/lib/geometry/hitTest.ts` performs precise hit testing:

1. Walk scene parts from topmost to bottom.
2. Skip hidden and empty layers.
3. Reject points outside the layer bounds in layer-local space.
4. Use `CanvasRenderingContext2D.isPointInPath` / `isPointInStroke` for the final decision.

This replaces the old fixed-size selection box and makes overlapping layers selectable accurately.

## Export

`src/lib/export/` is independent of React:

- `frames.ts` plans output frames from the 60 FPS source. It always exports the complete loop and never duplicates the boundary frame.
- `render.ts` paints a single frame to an offscreen canvas at the requested resolution.
- `gif.ts` renders canvases and hands them to `gifshot`.
- `mp4.ts` encodes H.264 with WebCodecs and muxes with `mp4-muxer`; if WebCodecs is unavailable it uses MediaRecorder and reports the real container (which may be WebM).
- `mov.ts` renders a PNG sequence and encodes ProRes 4444 with `ffmpeg.wasm`. If `prores_ks` is unavailable it retries with `qtrle`, which also supports alpha.
- `types.ts` defines progress stages, cancellation, and results.

`ExportModal` owns the AbortController, progress UI, cancellation, and object-URL cleanup. Long jobs yield to the UI between frames.

The ffmpeg wrapper and core (`ffmpeg-core.js`, `ffmpeg-core.wasm`) are served locally from `public/ffmpeg/` (generated by `scripts/sync-ffmpeg.mjs`) rather than bundled or loaded from an external CDN. Bundling the package breaks Turbopack on the wrapper's `new URL(..., import.meta.url)` worker bootstrap, and loading from a CDN risks CORS, latency, or network blocks. Serving both wrapper and core same-origin ensures reliable, offline-capable MOV exports.

## AI

`src/lib/ai/` contains:

- `settings.ts` — zod-validated localStorage settings with legacy upgrade.
- `prompt.ts` — builds the system prompt from live project state and the preset catalogue.
- `transport.ts` — direct or relay request with a 60 s timeout and abort support.
  It requests `stream: false` but normalizes SSE, JSON, and plain-text bodies via
  `parseCompletion.ts`, because some gateways stream regardless.
- `parseCompletion.ts` — tolerant completion parser (`message.content`,
  `delta.content` chunks, error envelopes, `[DONE]`, mislabeled content types).
- `actions.ts` — zod-validated action schema, response parser, and pure document
  reducer used by the auto-apply flow.
- `proxyGuard.ts` — pure URL, allowlist, and private-address checks used by the route and tests.

### Auto-apply flow

The system prompt requires a single JSON object:

```json
{ "reply": "Made the body bigger and switched to matcha.", "actions": [] }
```

`AISidebar` parses the completion with `parseAIResponse` (also accepting fenced
JSON, bare action arrays, and plain prose), validates every action with
`aiActionSchema`, and passes the valid subset to
`useStudioState.applyAIActions`. The reducer is pure and immutable; the whole
batch is committed through the history layer as one `Apply AI changes` entry, so
a single undo reverts it. Unknown layer ids, palettes, presets, and invalid
fields are skipped and reported under the chat message instead of failing the
batch. The prompt tells the model to emit actions only when the user explicitly
asks for a change; advice questions return `actions: []`.

The relay route adds a 64 KB body cap, a 30 s upstream timeout, a per-IP in-memory rate limit, `redirect: 'error'`, DNS resolution checks, and SSE passthrough. It never logs API keys and sanitizes upstream error text.

See [AI-RELAY.md](AI-RELAY.md) for the threat model and deployment notes.

## UI shell

- `MotionTrackStudio` composes the toolbar, sidebars, canvas, timeline, and modals.
- `components/ui/Modal.tsx` provides focus trapping, Escape handling, scroll locking, and focus restoration.
- `components/ui/toast.tsx` provides non-blocking feedback; the studio no longer uses `alert()`.
- `components/ui/ErrorBoundary.tsx` prevents a render failure from blanking the whole app and points the user back to the autosaved draft.

## Tests

Vitest runs in jsdom. Tests cover history semantics, project parsing and migration, frame planning, prompt construction, relay guards, bounds helpers, and clock behavior. The CI workflow runs lint, typecheck, tests, and a production build.
